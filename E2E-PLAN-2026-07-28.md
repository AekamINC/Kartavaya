## Ground rules

- **Never `kartavaya.com`** — that is production, 11 routers, 12 real users.
- **Login is the owner's to perform.** I cannot type a password into a form. Owner
  authenticates once per account, I drive from there. Three accounts:
  god mode · org owner · org member. Ten seconds each, three switches total.
- **Outbound stays off.** `OUTBOUND_MODE` governs email/WhatsApp/push. Verify up
  to the send boundary and stop. WhatsApp is **out of scope** by decision.
- **Core PM writes are visible to production** — `tasks`, `teams`, `users`,
  `boards` are shared rows. Prefix anything created there `E2E-TEST-` and delete
  it. The ten modules live in `staging.*` and production cannot see them.
- Synthetic data only. No real names, GSTINs, PANs or Aadhaar numbers.
- **No pricing figures anywhere.**

## Order of work

Modules first (invisible to production, so failures are cheap), core PM last.

### 1 · Per-module CRUD — the bulk of the run

For each of **Graha, Ganit, Manav, Vetana, Vikray, Prachar, Dristi, Srijan,
Sanvaad**: create → read in list → open detail → edit → verify the change
persisted after a reload → delete/deactivate. Nine modules × ~4 events ≈ **36
real events**, which is the 30–50 target.

Watch on every one:
- the empty state before the first record, not just the populated state
- validation: submit the form blank, and with one required field missing
- does the list actually refresh after create, or does it need a manual reload
- the 14 tables created last night are exercised here for the first time:
  Graha automations · custom fields · scoring rules · territories · web forms ·
  contact merges · tickets · inbound emails, plus `projects`,
  `approval_requests`, `hub_oauth_states`, `hub_skill_feedback`. **These have
  never had a row written to them.** A 500 here is new, not pre-existing.

### 1b · Every TAB, not just every page

Most modules are tabbed, and a tab that never mounts is the classic place a
defect hides — the page loads green and one tab inside it is broken. Click
**every tab on every page**, including the ones nobody demos: Srijan hub tabs
(DataCatalog, DataRuns), Graha tabs, Ganit tabs, org settings tabs (incl.
TabBilling, which `/billing` now redirects to), the customize hub tabs, Vikray's
four. Confirm each mounts, fetches, and renders its empty state.

This is where the count goes past 50: ~9 modules × CRUD ≈ 36, plus ~20 tabs,
plus the sections below.

### 1c · Data scrapers — run them properly

Owner has authorised the Apify spend, so test these for real rather than
skimming. Run several scrapers end to end, across different catalog entries and
input shapes, including one that returns a large result set and one that
returns nothing.

- Catalog (`hub_scraper_catalog`) lists, filters, and shows the right inputs.
- A run goes queued → running → finished, and the UI reflects each transition
  rather than sticking on "running" until reload.
- Results land in R2 and the download works.
- A run that FAILS is handled — error surfaced, not a silent empty table.
- **The check that matters most, and it is a leak not a cost question:**
  `cost_usd` must be absent from every tenant-facing response. It is Aekam's
  upstream cost basis, and beside `billed_inr` on the same row it discloses the
  margin by subtraction. `_TENANT_RUN_FIELDS` in `routers/scrapers.py` is an
  allow-list built for this. Verify it holds in the LIVE response body, not
  just in the source — read the actual JSON.
- Credits: confirm `billed_inr` and the credit ledger move by the right amount.

### 1d · AI queries and the chatbot — run them properly

Spend is authorised here too. Exercise it rather than sampling.

- Many queries across modules, not a handful. Short, long, empty, nonsense, and
  one deliberately ambiguous.
- Grounding actually grounds — answers cite real data from the org, and an
  org with no data says so rather than inventing.
- Streaming renders progressively and does not drop the last chunk.
- `hub_ai_logs` records each call and which provider answered.

- **No figure is shown that should not be.** Same class of leak as above.

### 2 · Cross-cutting interactions

- **Comments** — add, edit, delete; @mention a user and confirm it resolves to a

### 4 · Payroll flow, end to end

Salary structure → payroll run → payslip generation → download. `POST
/payroll/process` is the heaviest handler in the codebase (14 sequential
queries) — time it and note anything above ~3s.

### 5 · e-Sign, full lifecycle

Create document → add signers → send → sign → completed state → audit trail.
Confirm final submission only happens after **all** signers, with missing ones
flagged. Signature canvas must be sharp on a high-DPI screen (the devicePixelRatio
fix) — draw and look at it.

### 6 · UI/UX conformance — against `design-reference/`, live

The reference JSX/CSS is the spec, not the prose `.md` files. On every page
visited above, check: spacing and hierarchy match, `k-*` component classes are
used rather than hand-rolled styles, bilingual pairing is right, **dark mode**,
and responsive at mobile width. Screenshot anything that diverges.
