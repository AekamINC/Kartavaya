# Full-product E2E programme — phased

Owner's scope, 2026-08-02/03: *"full e2e from core PM, to pahchan to payroll,
ganit specially, MARKETING, automations, time report, templates, full CRM each
tab each function, same for sales, invoices, HRMS(Manav) onboarding, offboarding
etc pdf download to onboarding pack, sanvaad apart from whatsapp as it needs to
be wired with api, Srijan with images, e-sign — I need downloaded signed
document as well not just certificate. All this individual test to be done at
least 30+ time manual CRUD via playwright no scripting."*
Then: *"same e2e on mobile build for android and then container app."*

**Ground truth this is measured against:** 110 tabs/surfaces across 22 page
directories. ~390 UI CRUD operations on web, ~90 more on mobile. Every operation
goes through a real form — no SQL, no API shortcuts. That rule is why this is
phased and not one pass.

**Standing rules that shape every phase**
- All writes land in org `64e7bea6` (E2E Test & Associates). `public` schema is
  shared with production — task/board/approval writes stay team-scoped.
- Never sends: WhatsApp, SES to real inboxes, Srijan AI paid runs.
- One commit per phase. Test-only phases touch `frontend/e2e-real/**` only.
- A phase is not done until its spec is green **and** the bugs it found are
  fixed. Bugs are not deferred out of a phase to make the phase look finished.

## Phase 0 — Fix the three things a test could only prove are broken

Writing a test that asserts "downloads a JSON file where the signed contract
should be" would lock the bug in. So these land first.

| # | Defect | Evidence |
|---|--------|----------|
| 0.1 | **E-sign produces no signed document.** `esign.py` ~735-752 serialises audit data to JSON, uploads `certificate-<id>.json` as `application/json`, and stores it in `signed_file_key`/`signed_file_url`. The source PDF is never combined with the collected signatures. `DetailTab.jsx:161` offers it as "Signing certificate". | 11 of 27 completed docs have even that; 16 have nothing at all |
| 0.2 | **Srijan images missing.** | 6 of 208 `hub_content_items` have an `image_url` |
| 0.3 | **Two ungated invoice paths** can still mint an un-issuable tax invoice via `doc_status` DEFAULT `'final'`. | `ganit.py` ~2272 `from-time-entries`; vikray `orders/{id}/invoice` |

Deliverable: stamped signed PDF + certificate as two honestly-labelled
downloads, a decision on the 16 orphan documents, images generated and rendered,
both invoice paths gated.
Gate: full backend pytest (1,973 baseline) + `npm run check`. **1 commit
(backend → 1 Railway deploy).**

## Phase 9 — Android

The existing debug APK is `mobile/android/app/build/outputs/apk/debug/app-debug.apk`
(174 MB, built 2026-08-01); EAS preview is configured in `mobile/eas.json`.

**Playwright cannot drive a native Android app.** Phase 9 uses **Maestro** —
YAML flows against the installed APK on an emulator, closest thing to the
"real user, no scripting" rule that exists for native. `adb` is not currently
on PATH here.

**Mobile is a deliberate subset, so "the same E2E" means the journeys that
exist there:** Today, Tasks, Boards, TaskDetail, Time, Approvals, Inbox,
Messages, Chat, Reminders, Me, Settings, ClientPortal, More, plus module
screens for Ganit, Graha, Manav, Vetana, Prachar, Srijan, Dristi, and the five
Pahchan screens (Clock, Enroll, MyBiometrics, MyRegister, AttendanceHistory).
≈ 90 operations, including offline queue and camera-backed enrolment.

## Cost note

Only phases that change `backend/**` need a Railway deploy — Phase 0 does, and
any later phase that finds a backend bug. Setting a Railway watch path of
`backend/**` on the staging service would stop test-only commits from
triggering a paid build at all.
