# E2E Plan — Playwright, full autonomy — 2026-08-02

Built from all 103 tracked markdown files (design-handover 00–27, docs/ + generated
module docs, READMEs, design-reference specs) plus the existing test infrastructure
(root e2e/, frontend/e2e/, vitest e2e suite, ci.yml). Single-threaded execution by
Claude; no subagents, no swarms. Batched commits only (every commit costs a Railway
deploy).

---

## 1. Ground truth today

- **Root Playwright suite** (`playwright.config.ts` + `e2e/*.spec.ts`, 6 specs):
  points at a deployed URL, real UI login per test, CI job literally named
  "writes to the shared database", gated off by default. Weak `.or()` selector
  chains, `loginAs` copy-pasted in 5 files, no storageState. Effectively dormant.
- **Frontend Playwright suite** (`frontend/playwright.config.ts` + `frontend/e2e/`,
  3 specs): the healthy pattern — localStorage seed + `**/api/**` stub +
  dead-port `VITE_BACKEND_URL` + `assertRendered`. Runs in **no CI job**.
  Two design-geometry tests are `test.fixme` (fixture endpoint shapes wrong, not CSS).
- **Vitest "e2e" suite** (`frontend/src/__tests__/e2e/`, runs in CI): strong on
  logic (auth, client isolation, entitlement `it.fails`, separated duty `it.fails`,
  Vetana states, move-is-one-call, pagination, CSS-text motion rules). jsdom —
  cannot do layout, real drag, real focus, computed styles, animations.
- **No browser test anywhere completes a write journey.** Nothing enforces
  read-only on the next root spec added.
- **Shared DB**: staging + production share one Supabase project. public schema
  (41 tables incl. users/teams) is shared; staging.* is org-isolated. Even login
  writes a session row. No-write-probes rule is standing (GSTIN incident 2026-07-28).
- **Design parity**: ~84% of reference class names absent from the build. Handover
  .md files mix TARGET spec with CURRENT defects; roughly half of all defect claims
  proved stale on verification. The reference JSX/CSS is the spec, the .md files are
  leads. Several "fixed in ledger" items must not be tested as bugs: TargetsTab,
  FocusTrap isConnected, addToast (d9638ae), Sanvaad scrollback (PR #41),
  ग्राह→ग्राहक, token alias layer.

## 2. Safety rails (baked into the harness, not policy)

1. **Tier-1 tests never touch any network**: every request stubbed via
   `page.route('**/api/**')`; `VITE_BACKEND_URL` stays a dead port so an escaped
   request fails loudly.
2. **Tier-2 (staging smoke) is structurally read-only**: a shared fixture installs
   a request blocker that **aborts every non-GET** except `POST /auth/login`.
   A spec cannot submit a form even by accident.
3. **Deployed-SHA gate**: Tier-2 runs first fetch the deployed SHA and skip the
   whole run if it doesn't match the expected commit (no-write-probes memory rule).
4. Never exercised anywhere: WhatsApp/Prachar sends, Srijan generation (credits +
   paid models), payroll approve/revert, esign/ganit OTP completion, org danger
   zone (module toggles, 2FA enforce, IP ranges, transfer, delete), impersonation,
   session sign-out-all, /admin/billing writes (no org_id — mutates operator's org).
5. Windows rules: vite bound to `--host 127.0.0.1`; never regenerate
   `frontend/yarn.lock`; stub `/auth/me` must echo the seeded user
   (Protected.jsx:91 overwrite); design-geometry pages need **bare-array** list
   bodies, f32 pages need the full envelope.

## 3. Architecture — three tiers

**Tier 1 — Stubbed UI suite (`frontend/e2e/`). The workhorse. ~90% of all events.**
Local vite + full API stubbing. Covers layout, computed styles, keyboard, focus,
drag, animations, responsive, dark mode, bilingual, RBAC gating — exactly what the
vitest suite declares it cannot. Write flows are covered as **contract tests**:
intercept the POST/PATCH, assert the exact payload the UI sends (the proven
skill-data-steps pattern). Zero DB risk, CI-able on every push.

**Tier 2 — Staging read-only smoke (root `e2e/` rewritten).**
One login per run (storageState reuse — one session row, acknowledged), then
per-route: loads, zero `pageerror`, breadcrumb, key landmarks, known-bug pins.
Non-GET aborted by fixture. Run manually or nightly after deploys, never per-push.

**Tier 3 — Real write journeys. Deferred.**
Only sane against a local full stack (uvicorn + seeded local Postgres via
`backend/seed.py`) — not planned until Tier 1+2 are done and the owner wants it.
The stub-contract tests in Tier 1 already prove the frontend's write behavior.

## 4. Phases (execution order)

### Phase 0 — Harness (one session)
- `frontend/e2e/support/` module: `seedUser(role, grants, levels)`,
  `stubApi(overrides)` (documents envelope vs bare-array per page family),
  `gotoReady(route)` (waits `.mh`/page-root, not the clock), `assertRendered`,
  route enumeration derived from `navConfig.js ROUTE_META` (never hardcoded),
  viewport presets 393/834/1440, theme/motion emulation helpers
  (`colorScheme`, `reducedMotion`, `k_prefs` seeding), en-IN money/date helpers.
- Kill the two `test.fixme`s in design-geometry by fixing fixture shapes
  (/boards and /dashboard fixtures don't feed those pages).
- Consolidate the root suite's `loginAs` into one fixture with storageState
  (used by Tier 2 only).
- **CI**: add a job running `yarn test:e2e:gating` (frontend Playwright) on every
  push — the cheapest coverage win available. Root suite stays gated.
- **Cost control**: configure Railway service watch-paths to `backend/**` so
  test-only commits stop triggering backend rebuilds; same idea on Vercel
  (ignored build step) for backend-only commits. One-time setup, directly cuts
  the per-commit deploy cost.

## 5. Known-bug ledger discipline

Every defect claim from the .md files is a **lead, not a fact** (half proved
stale). Before writing any expectation: read the current source, decide
`@pin-current` (bug still live — assert today's behavior so the fix is detected)
vs `@target` (fix landed — assert fixed behavior). Never assert both. Tags make
the flip a one-line change.

## 6. Runbook

- Local: `cd frontend && yarn test:e2e:gating` (stubbed suite, starts vite itself).
- Staging smoke: `PLAYWRIGHT_BASE_URL=https://staging.kartavaya.com npx playwright test`
  from repo root with E2E creds set; SHA gate aborts on mismatch.
- CI: stubbed suite on every push (new job); staging smoke stays manual.
- Reports: absolute dates only; event counts per area reported against the
  50-per-page floor. (Optional: results can be pushed to Qase via the connected
  MCP if wanted.)
- Commits: one batched commit per completed phase, on `staging`, never per-spec.

## 7. Explicitly out of scope

Mobile app (React Native), push notifications (stub), exports (pinned
expected-broken), calendar/timeline/workload/priority interactions (unspecified),
real WhatsApp/SES/Srijan-AI side effects, Supabase Realtime multi-user unread
(needs two live sessions on shared DB — revisit in Tier 3), >200-row list
assertions (truncation), pixel-PNG baselines (Windows-authored pixels fail Linux
CI — text baselines remain the rule).
