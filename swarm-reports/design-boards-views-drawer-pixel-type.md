# Boards, views and the task drawer — pixel and type

Branch `design/boards-pixel-type`. Both sides **rendered**, never read. Every
number below came out of `getComputedStyle` on a live node and the comparison
table at the end is generated by a script — nothing in it was transcribed.

## How it was measured, because the last three runs could not reproduce theirs

The shared browser MCPs are unusable for this: sibling agents were driving the
same tabs, and two of my early readings landed on someone else's page
(`_COORDINATION.md §0b` records the same thing happening to others). The fix was
to stop sharing a browser at all.

```
frontend/__measure/            # committed, dev-only, not in the build graph
  ref.html + ref.js            # loads the reference harness in a same-origin
                               # iframe, clicks Boards, opens a card, then Tasks
  index.html + main.jsx        # mounts the REAL build components — KanbanView,
                               # TaskCard, ViewToolbar, TableView, TaskDrawer,
                               # PageHeader — against the real stylesheet graph
  measure.js                   # the ONE probe routine both sides run
```

The build harness swaps `api.defaults.adapter` for a local resolver **before any
component mounts**, so the board and the drawer fetch nothing: no request leaves
the page and the shared database is never touched.

Both pages are then driven headless with a private Chrome profile and read back
off disk, which removes the browser race entirely:

```
chrome --headless=new --user-data-dir=<fresh> --virtual-time-budget=60000 \
       --dump-dom http://localhost:5931/__measure/ref.html
```

Reproduce: copy `design-reference/Kartavaya Redesign/*` into
`frontend/public/__ref/`, `npx vite --port 5931` from `frontend/`, then dump both
pages and diff the two JSON blobs. `frontend/.env.local` needs any
`VITE_BACKEND_URL` — `lib/api.js` throws at import without one.

## Baseline, settled before anything else was read

| | reference harness | build |
|---|---|---|
| `data-density` | `cozy` | absent in harness; `comfy` at runtime |
| `data-display` | `serif` | attribute does not exist |
| `--radius-base` | `12px` (`App.jsx:3`) / `10px` (`SetCustomize.jsx:470`) | `10px` |
| `--font-ui` | `Public Sans` (stylesheet fallback) | `Inter` — and Inter is the reference's runtime default too |

Two things this settles, both already in `_COORDINATION.md §0c` and confirmed
here independently:

- The reference's density control offers Compact/Comfy and **writes `cozy` for
  Comfy** (`SetCustomize.jsx:491`). `cozy` is therefore the reference's real
  default. The build's `:root` already carries cozy's exact numbers
  (44 / 28 / 18 / 22 / 10) — the only thing wrong is that `DEFAULTS.density`
  points at `comfy`, a step the reference never resolves to.
  **Not fixed here, per the standing instruction.** Every number below is
  measured at the matched cozy baseline, so none of it is contaminated by it.
- `--font-ui` Inter-vs-Public-Sans is a **harness artefact** — the reference's
  own `CUST_DEFAULTS` is `uiFont: 'inter'`. Every `font-family` row marked ⚠
  below is this and is **not a defect**. Sizes, weights and tracking are real.

One correction to `_COORDINATION.md §0c` offered rather than asserted:
`--radius-base` may not be a fallback-only difference. The **product** harness
(`App.jsx:3`) renders the whole app at `radius: 12`; `SetCustomize.jsx`'s
`radius: '10'` is that settings screen's own demo slider position, not a product
default. All three residual mismatches below are this one token. I did **not**
touch it — I corrected the radius *steps*, which are base-independent, and left
the base to whoever owns tokens.

## Result

**37 of 40 load-bearing measurements now match the render exactly.** The three
that do not are all `--radius-base` 10-vs-12.

## What was wrong, and what changed

### Board and column — `.board` / `.bcol` vs `.bd` / `.bd__col`

| | reference | build was | build is |
|---|---|---|---|
| board gap | 10px (`--gap-tight`) | 12px literal | `--gap-tight` |
| board trailer | 6px | 10px | 6px |
| column padding | 11px | 10px | 11px |
| column gap | 9px | 8px | 9px |
| column radius | 17.4px (`--r-lg`) | 10px (`--r-md`) | `--r-lg` |
| column min-height | 180px | auto | 180px |
| head clearance | 9px + 1px rule | 8px, no rule | 9px + rule |
| colour mark | 4×16 bar, r2 | 8×8 dot, r50% | 4×16 bar |
| title | 12.5 / 700 / +.03em | 13 / 800 / −.005em | 12.5 / 700 / +.03em |
| count | pill, 10.5px mono on `--s-container` | bare 11px mono | pill |

The board gap was a **literal**, so it was the same gap at every density
setting — the one thing the density control exists to change. The column radius
was one token step down, which is why a column read as a card rather than as the
ground a card sits on.

### Card — `.bcard` vs `.bc`

| | reference | build was | build is |
|---|---|---|---|
| radius | 12px (`--r-md`) | 5.8px (`--r-sm`) | `--r-md` |
| resting shadow | none | `--shadow-1` | none |
| gap | 8px | 7px | 8px |

signal the lift has. `.bc.drag`'s `--shadow-2` is untouched — that belongs to the
motion agent and it was already right.

### Devanagari — the recurring defect, found again

`BoardsPage` passed `kicker="AEKAM INC · फ़लक"`. Measured, that put Devanagari
inside a node at **`letter-spacing: 2.42px`** and **`text-transform: uppercase`**,
both forbidden by `24-bilingual-devanagari.md`. `editorial.css` had noticed —
there was a comment naming this exact call site — and had responded by adding
`var(--font-hindi)` as a fallback family so the wrong node could at least draw
the glyphs.

The term now goes to `sanskrit`, which is where the reference renders it
(`.ph__hi`, beside the title at headline size in `--primary-text`) and where the
build had **no node at all** on this page. `.k-pageh__kicker` loses the fallback
family and gains a `:lang(hi)/:lang(sa)` guard for any caller that still mixes
scripts.

`.k-pageh__sans` now declares `letter-spacing: normal` instead of inheriting the
display face's −.02em. **This is a defect in the reference too**: `ph__hi`
measures −0.56px there. Tiro is a single-weight face designed on its own fit and
negative tracking collapses its conjuncts, so the token rule wins over the
reference on this one point — recorded rather than done silently.

`फलक`, not `फ़लक`: the nuqta on फ़ is the Perso-Arabic /f/ and does not belong in
*phalak*. `navConfig` and the reference both spell it without.

## Open, not fixed — with numbers, for whoever owns them

**1 · `--radius-base` 10 vs 12 (tokens).** Every remaining mismatch. At 10 the
column corner is 14.5px against 17.4px and the card is 10px against 12px. The
steps are now correct; only the base is out. See the note above — I think the
product harness (12) is the pixel source and `SetCustomize`'s 10 is a slider
demo, but this is a token-owner call, not mine.

**2 · The view toolbar is a different object (structure).** Not a size gap.

| | reference `.tabs` | build `.vtb` + `.k-segctrl` |
|---|---|---|
| form | underline tabs on a 1px rule | pill segmented control, no rule |
| height | 41px (button `min-height: 40px`) | 35px (button 27px) |
| button | 12.5px / 600, padding 9/13, 2px active underline | 12.5px / 600, padding 6/14, `--r-sm` pill |
| bilingual | `.tabs__en` + `.tabs__hi` — Kanban/फलक, Table/सूची, Calendar/पंचांग, Timeline/कालरेखा, Workload/भार, Priority/प्राथमिकता, Mytasks/मेरे कार्य | Latin only |

The Latin words also differ (`Kanban`/`Table` vs `Board`/`List`), which
`_DESIGN-GAP.md §2` says to settle deliberately rather than silently. Left alone
on both counts.

**3 · Column Devanagari cannot be fixed in CSS.** `.bcol__hi` renders on every
reference column; `.bd__cn-hi` renders only for the two synthetic columns
(`Requested`, `Awaiting Client Approval`), because a user-named column has no
Devanagari field to render. Needs a data decision, not a style one.

**4 · Page header title scale (shared, likely the dashboard/tasks agent's).**
`.ph__h1` is `--t-headline` = **28px** at line-height 1.3. `.k-pageh__h1` is
`clamp(32px, 4vw, 44px)` at line-height 1 — **44px** at 1440, +57%. This cascades:
`.k-pageh__sans` at `0.7em` measures 30.8px where the reference's `1em` measures
28px. Kicker is 11px/.22em against 10.5px/.2em. There is a
`design/dashboard-tasks-pixel-type` worktree in this run; leaving it to them
rather than colliding.

**5 · Avatar primitive, 1px and 1px (`components.css` / `ui/Avatar.jsx`).**
At the corrected 22px, initials render 9px (`Math.round(size * .41)`) against the
reference's 8px, the ring is 1.5px against 2px, and the overlap is −6px against
−7px. Three one-off values in a shared primitive; not my files.

**6 · `--ease-emph` differs at the token, not at the drawer (motion).**
`drawer.css` correctly says `--ease-emph`, but the build's token is
`cubic-bezier(.16, 1, .3, 1)` where the reference's is `cubic-bezier(.2, 0, 0, 1)`.
So the recorded "drawer easing resolved toward the reference" fix is in place and
still renders the wrong curve. Same for `.dr__scrim`: `--ease-enter`
(`cubic-bezier(0,0,.2,1)`) against the reference's `--ease-emph`. Durations all
agree (drawer .36s, scrim .22s). Motion agent's call.

**7 · The reference board is fluid; the build's is rigid (structure).**
`.board` is `grid-auto-flow: column` with `grid-auto-columns: minmax(268px, 1fr)`
— four columns spread to 275.5px each in a 1132px content box, and they grow with
the window. `.bd` is `flex` with a fixed `width: 288px`. Given the owner rule
"all pages fluid, no fixed-width centring", the reference's grid is the one that
obeys it. Structure agent's call; I left the 288px alone.

**8 · `--shadow-4` differs (tokens).** Reference
`0 24px 56px -12px rgba(30,28,22,.30), 0 8px 20px -8px rgba(30,28,22,.16)` —
two layers. Build `0 32px 72px -28px rgba(30,28,22,.38)` — one, larger, darker.
It is the drawer's shadow, so it shows on this surface, but the token is global.

## Gates, and one that is falsely red in every worktree

- `npm run check` — **pass** (tokens 0 missing, classes 0 missing).
- `npm run build` — **pass** (3m06s).
  Note: it was *failing on my branch point* on `DristiPage.jsx:581`, an
  `{/* … */}` JSX comment used inside a ternary's parenthesised expression, which
  is an object literal there. A sibling has since fixed it on staging; recorded
  only so nobody re-diagnoses it.
- `npx vitest run` — **435 passed, 1 failed.**

The one failure is **not a regression and not anyone's code**:
`e2e · visual · the theme palette baseline` compares a snapshot string against
`__snapshots__/visual-regression.test.jsx.snap`, and with `core.autocrlf=true`
that file lands **CRLF in a fresh worktree** while vitest serialises LF.

Proof, both directions:

```
worktree copy : CRLF 92, bare LF 0     -> test fails
main checkout : CRLF  0, bare LF 92    -> test passes
```

and the test fails **identically with all five of my files reverted to
`origin/staging`** — verified, then restored.

Fix is one line in `.gitattributes`, and I have deliberately not applied it:

```
*.snap text eol=lf
```

Renormalising a tracked file mid-swarm would dirty every other agent's worktree
at once. It should be one coordinated commit. Until then, **every worktree will
show this red, and it means nothing.**
