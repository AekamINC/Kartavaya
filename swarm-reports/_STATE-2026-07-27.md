## 2 · What was actually broken

Not styling. Every one of these was live, and none was found by a failing test:

**Data crossing a tenant boundary**
- The dashboard `deadlines` widget returned the fifteen nearest task titles and
  assignee names **from every team in every organisation**, to any authenticated
  user. No privilege needed — only a widget saved with no project selected. The
  sibling widgets compare `team_id=$1` and fail closed; only this one inverted
  the test and failed open.

**The product dying**
- **Finishing onboarding crashed the whole app.** A hooks-order violation fired
  the moment a firm completed all four setup steps, and the component is mounted
  outside the page error boundary, so it took the sidebar with it. Every new
  customer, days after signing up.
- A tab throwing used to blank the entire product; there is now a page-scoped
  boundary so the shell survives.
- `/admin` and `/admin/billing` crashed outright.
- `srijan/DataCatalogTab` unmounted its whole module on a JSON-string schema —
  a shape `routers/scrapers.py:160` explicitly handles, which is the evidence it
  occurs.

**Features that had never worked once**
- **Sanvaad could not load a single message.** `staging.users` does not exist and
  `public.users` has no `avatar_url` (the column is `avatar`) — two independent
  hard errors, so every read endpoint 500'd. It had a green suite the whole time,
  because `pytest` mocks the pool and a mocked cursor never resolves a table name.
- **The Ganit e-sign flow could never send.** Four faults under one
  `except Exception`, answering `{"status": "sent"}` with nothing sent. Fixing
  the import alone would have given every signer the *same* token.
- `POST /api/time/manual` 422'd on every call — a required field was never sent.
- The Manav leave-clash check omitted a required field and 422'd every time.
- Vikray stock never moved: confirming an order deducted nothing, forever.
- Pahchan retakes never reset — after three failures every later punch was
  flagged for a manager, including a clean clock-out an hour later.

**Lying to the user**
- Failures rendering as empty states, found in *every* module: "No payroll runs"
  (nobody is owed anything), "No employees yet", "No pending requests" over a
  queue that never loaded, "No transactions yet" over a spending wallet, a
  confident **0h** on Time Report, and on mobile "All clear! No tasks" on the
  first screen a user opens each morning.
- Graha's follow-up filter was inverted: choosing **Completed** showed the open
  list.
- Every dead approval link told the visitor *the server broke*.
- `TeamsPage` showed project A's members under project B's name.

**Reaching people**
- Five email templates interpolated user text straight into HTML. A contract
  titled `<img src=x onerror=…>` executed in the recipient's inbox.
- Every weekly digest rendered `सप्ताह का नाय??` — two corrupt bytes.
- Both public pages had **2.13:1** Devanagari in dark, on the page a client's own
  customer approves work from.
- The primary button was **2.51:1** in light across 145 uses.
- `--side-fg-faint` was **2.52:1 / 2.06:1**, carrying twenty text elements on
  every page including the whole bilingual sidebar.

### Late additions — the signing page, audited after this file was written

Three lenses on `SigningPage.jsx` alone, because it is public, holds a bearer
token in the URL, and is where a client's own CUSTOMER applies a signature that
the page itself calls binding under the IT Act 2000.

- **A blank canvas could be filed as a signature.** The signature pad's ref
  callback was an inline arrow, so React reattached it on every render and
  repainted the canvas; nothing then checked whether it held ink. Measured in
  pixels: **1129 → 0** the instant the Decline dialog opened. Draw → open
  Decline to read what it means → Cancel → Sign produced a blank PNG and
  *"All signatures collected."*
- **The signing token was being sent to Vercel.** `@vercel/analytics` reports
  `location.pathname` verbatim, so every `/sign/<token>` visit handed the full
  signing authority to a third-party dashboard. Now redacted before the event
  leaves the browser — for `/sign`, `/approve`, `/accept-invite`,
  `/reset-password` and any `?token=`.
- **A cancelled or expired document could still be signed.** The read path
  refused it; the write path never checked, and the POST replays without the
  page.
- **The OTP limiter permanently disabled itself** after its first window —
  unlimited guesses at a six-digit code, forever.
- A 500 on the initial read left the page with **zero buttons and zero links**
  under copy reading "Try again in a moment", with no nav to escape through.
- Offline said *"Changes are saved and will sync when you're back."* This page
  saves nothing.

Two questions worth keeping in that form:
**Can anyone sign as anyone else? No** — identity resolves server-side from a
256-bit token, and `otp_verified` defaults to `false` (checked against the live
catalog, so OTP is not skipped).
**Can a signature be repudiated? Yes** — `_generate_signed_certificate` uploads
JSON and hashes *that*, not a document. No signed PDF is ever produced, and the
emailed copy the signer is promised has no code path. The counterparty holds
nothing. **This is the most serious open item in this file.**

## 4 · Decisions waiting on you — 11

Four are a word each; the rest need a designer or a product call. Two more
arrived with the signing-page audit and are marked NEW.

1. **TDS challan: 285mm or 290mm.** At 285 a three-line challan splits across two
   pages and orphans the CIN. 290 puts it back on one sheet with 7mm spare. My
   recommendation is 290 — these are emailed PDFs, not printed.
2. **The landing page CTA has no destination.** `VITE_LEAD_CTA_HREF` is unset and
   the page tells visitors so.
3. **Five chip contrast ratios** (4.13–4.37). A chip tinted with its own
   foreground; the remedy that fixes one destroys the colour coding on three.
4. **`lib/utils.js` palettes** — 7/7 avatar and 9/10 project colours fail
   white-on-swatch. Needs a replacement palette.
5. **A `viewer` can write on 210 of 234 module-gated write routes.**
   `require_module` checks only that a grant ROW exists, and every new grant and
   invite defaults to viewer. Picking the right rung per route is a product call.
6. **July 2026 GSTR-3B hard-locking** — ITC becomes non-editable and
   auto-populates. Mechanically fine for a working paper; unassessed for workflow.
7. **Vikray pipeline: order lifecycle or real quotes?** A true quote pipeline
   lives in `ganit_invoices` and would need the Ganit gate stacked, which would
   403 every Vikray-only member.
8. **NEW — every Ganit contract signing link is dead.** `esign_service` mints a
   `ganit_contract_signers` token; `/sign/:token` queries `sign_signers`. Two
   namespaces collide on one route, so every Ganit signer gets a 404 rendered as
   "This doesn't exist, or it was deleted." Teach the page both protocols, or
   give Ganit its own route. Confirmed independently by two lenses.
9. **NEW — signing order is never enforced.** `sign_order` is stored and ordered
   by, never gated: signer 3 can sign before signer 1.
10. **Sanvaad's default grant level** — `viewer` per spec, or `editor`? Zero rows
    to migrate, so it is free to change today and not tomorrow.
11. **GSTR-3B `4(D)(1) <= 4(A)(5)`** — blocking, as built, or advisory?

## 5 · Not verified — the honest list

1. **Nobody has looked at this product.** No browser frame composited in the
   entire session; every visual claim is measured layout, not appearance. This is
   the largest remaining risk and no agent can close it.
2. **Sanvaad end-to-end.** The queries are proven against the live schema — the
   directory query returns real rows — but the flow has not been exercised.
   Open it on staging.
3. **Mobile renders.** Node strips types but does not transform JSX, so no
   `.tsx` renders in tests. Gestures, haptics, camera, sheet presentation,
   animation, touch-target size and whether Tiro actually loaded are all unknown.
4. ~~`nixpacks.toml` installs no fonts.~~ **Checked, and this was overstated by
   me — it is not a deploy risk.** The Devanagari face is *vendored*
   (`backend/assets/fonts/TiroDevanagariHindi-Regular.ttf`, committed), and
   `doc_fonts.font_face_css()` declares it with a `file://` src precisely "so
   resolution does not depend on fontconfig finding anything". `backend/
   Dockerfile` does `COPY . .`, so the file ships, and it installs the
   libpango/pangoft2/pangocairo shaping stack. `railway.toml` declares no
   `[build]`, so with a Dockerfile present that is the path taken; the nixpacks
   fallback lists pango, fontconfig, freetype and harfbuzz anyway. Both paths
   work. The one residual is Latin substitution, which could still differ from a
   local render — Devanagari cannot, because the face travels with the code.
5. **Field-name agreement is partial.** 156 of 279 GET routes use `SELECT *`, so
   a frontend key that does not exist cannot be seen from source alone.
6. **`.cbx` at 17×17** — measured, unfixed, system-wide blast radius.
7. Emails have never been opened in a real mail client.

## 6 · Two things worth knowing about how this was checked

**Agents nearly filed ~40 false findings between them**, and each was caught by a
control rather than by luck — wrong fixture field names, a colour instrument
compositing over a transparent gradient stop (52 phantoms), a parser blind to
`color(srgb …)` that made its own fix measure clean at 3.83:1, and an
`innerText` artefact that looked like glued scripts. Every one was recorded as
*disproved*. That is why the rest of these reports can be believed.

**A gate that runs nowhere is worse than no gate.** `check-contrast.mjs` existed,
was correct, and had never been invoked — which is how five failing pairs were
signed off by two separate audits. It is now wired, baselined at the 20 known
pairs so it cannot block on decision 3 above, and fails on anything new or
anything that regresses. `contrast-baseline.json` is the record of what was
accepted; shrinking it is the direction of travel.
