Decisions we need from youनिर्णय

Seven things the design surfaced that are business calls, not design calls. Each is designed both ways where that was possible. All seven are now settled.

09
01Decided — invite-only.There is no public signup. The landing page now says “Request access”, not “Start free”, and makes no trial promise. The self-serve path stays designed in AUTH-SPEC.md for whenever you want it.
02Decided — the app is built new.Nothing is live, so there is no palette migration to manage. tokens.ts gets authored from the web tokens on day one and the two surfaces stay in step from the start.
03Decided — sensitive modules follow the org role.Payroll, accounting and HR are not granted per member at all. Owner and Org admin have them, nobody else does. The matrix cells are locked rather than pickable, so nobody can quietly grant payroll to a manager.
04Deleting an organisation waits seven days.Queued rather than executed, recoverable in that window. Worth confirming that matches what you would want to promise a customer.
05Support access is never silent.When Aekam staff enter a customer's workspace it is logged in the customer's own audit trail and the owner is emailed. There is no quiet mode, by design.
06Decided — Sahayak ships on cream.The prototype's palette, matched exactly. Upstream's built sahayak.css scopes the Slate/indigo surface theme; removing that scope is the whole change, since nothing in the prototype carries a literal colour. The contrast pass has to be run again on cream and dark — the existing measurements were taken by hand against Slate.
07Decided — the skills request endpoint is in scope.POST /v1/hub/skills/:id/request: a free-text note, idempotent per organisation and skill, landing as a lead for the account contact and emailing them. The card reads the state back — Available, then Requested, then Active — so nobody presses it twice.
