etc you are full approved for crud."* Do not stop to ask before changing infrastructure.

What that removes is the asking, not the care — and the care is not politeness, each of
these has already cost this project something:

- **Staging and production share one Supabase database.** A migration touches production
  data whoever approved it. State write-path effects before running one; back up before
  anything destructive. The 22 Aug QA cleanup is the model — restore schema first, delete
  set frozen so it cannot drift, children before parents, counts verified after.
- **Railway:** run `railway config plan` and read the diff before `apply`. A redeploy
  reuses the old config snapshot, so a service can look armed while running the old command.
- **Vercel:** `vercel.json` accepts no comments — a `"//"` key kills the deploy before the
  build starts, with no logs, and the site silently stays on the old build. Vercel is also
  the DNS provider.
- **Sentry:** the scrubber once redacted `event_id` and Sentry rejected every event.
