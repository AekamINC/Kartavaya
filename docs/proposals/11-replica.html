The greeting and four openers replace "Pick a conversation, or start one." The answer is rendered markdown — today that same reply prints as literal ## and **. Citations are numbered inline and the source list labels KB against WEB, because the two carry different fields and a client reading "from your knowledge base" must be able to tell.

Not shown, deliberately. No image generation. Chat is never routed to an image provider and the system prompt refuses the request — images are 80% of the AI bill, and "make me a logo" is exactly the ask that would run it up.
The one decision this raises. These two screens would no longer match the rest of Kartavaya, which is warm cream. That is defensible — Slack does not look like the apps around it either, and messaging is the surface a client judges hardest. But it is a real fork with three answers, and it is yours: (a) messaging and chat get their own theme, as shown; (b) the whole product moves to this palette, which is a much larger change and touches every module; or (c) keep cream everywhere and take only the depth — the shadows, the gradient bubbles, the jewel channel tones — which lifts it without the fork. Tell me which and I will build that one.
What this replica does not promise. Fonts render in fallbacks here — the product loads Inter and Newsreader, which a self-contained file cannot. Streaming shows as a resting three-dot state, not animated token-by-token; real streaming needs SSE in the backend and is not in this scope. And these colours are not yet declared tokens — npm run check would reject them as raw hexes, so approving this means adding them to the palette file first.
