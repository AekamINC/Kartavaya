Bilingual welcome — six variants

Direction C, taken further. All in the approved Slate / indigo.

First — will it actually understand Hindi, Gujarati and English?
YES, it will understandGemini, Qwen and GLM are all multilingual. A question typed in Hindi or Gujarati gets a sensible answer today.
But by luck, not designhub_chat.py:402 hard-codes language="en". The router HAS an Indic branch — INDIC_LANGS routes hi/gu/bn/ta and six more to models chosen for them — and it is never reached.
And it may reply in EnglishNothing in the system prompt tells it to answer in the language it was asked in. So a Gujarati question can come back in English, which reads as the assistant ignoring you.

The fix is three lines, and it belongs with the two-line model-chain fix already queued: detect the script of the incoming message, pass that as language instead of the literal "en", and add one sentence to the system prompt — reply in the language the user wrote in. Worth knowing that Gujarati is weaker than Hindi in every one of these models, so it is worth testing before it goes in a demo.

My pick is C4. It keeps C's bilingual warmth and adds the sentence that turns the RBAC work into something the client can see. If the demo needs to land harder in three seconds, C5 — but only once the counts are real.

Just note the caveat above — Gujarati is the weakest of the three in every model we route to, so advertising it means testing it first.
