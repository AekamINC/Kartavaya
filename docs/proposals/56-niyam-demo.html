Why a broken rule cannot be written

When , only if

1 · niyam_events — the outbox

#eventactorsourcestate
In production this runs every minute.

Events are written in the same transaction as the business change, so an event exists only if the change committed. actor and source are real columns — an app event with no actor is refused, which is how production writing to this shared database can never impersonate a user here.

2 · niyam_runs — one per rule, per event

runruleeventoutcome

Claimed by insert on UNIQUE(rule_id, event_id). Sweep twice and nothing doubles — the second claim loses the race and skips. Try it.

3 · outbound_log — the only record of a send

tochannelwhatstatus

The engine stores no “sent” flag of its own — a run step points here, so delivered, suppressed and never recorded stay three different answers instead of one optimistic boolean.
