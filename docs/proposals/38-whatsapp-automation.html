Guardrails — not optional

✓Reminders stop the moment it is paid. Chasing a settled invoice is the fastest way to get a number reported.
✓Quiet hours. Nothing sends outside the org's stated window — default 09:00–19:00.
✓One message per invoice per day, however many rules fire.
✓Opt-in required. A contact with no recorded opt-in is skipped and listed, never sent to.
✓STOP unsubscribes, and no rule can override it.

These protect the org's own number. A WABA that keeps sending unwanted messages is throttled by Meta and eventually flagged — the same warning already written into whatsapp.py:341 about the 24-hour window.

05 What it actually takes to build
The webhookAn inbound endpoint with Meta signature verification, handling sent / delivered / read / failed and inbound replies. Without it the button sends into silence — which is what option 3 already does for free, so this is the piece that makes P7 worth paying for.
Finish the sendsend_wa_message writes a row pending behind TODO: Call Meta Cloud API (whatsapp.py:334). It also already enforces Meta's 24-hour window server-side, which templates are exempt from — that branch needs to know the difference.
Template registryTemplates, their category, their Meta approval state, and which rule each one gates. Rejections must surface with Meta's reason.
Opt-in ledgerTimestamp and source per contact. A checkbox nobody records is not consent, and Meta requires it before any template send.
Migration 127127_connector_credentials.sql exists as a file and my note says it was never applied — so there may be nowhere to store an org's own WABA token yet. Verify against the live database before this is sold.
SchedulerThe reminder rules need a daily job. Crons are already armed on staging in Singapore — this becomes one more grouped service.

Two things that are true whatever we build.

  • Meta bills the org, not Aekam. The WABA is theirs, so utility conversations are charged to their account. You sell the automation and never resell messages — no margin to defend, no usage bill arriving here.
  • "Paid" still comes from the bank. There is no gateway and therefore no payment callback. Every automation that depends on knowing an invoice is settled runs on reconciled bank data, with whatever lag the org's bank import has. The receipt message is not instant, and promising otherwise would be a lie the first customer notices.
