Policy — what this needs, and what it doesn't

  • Cookie banner: NOT neededthe product sets no third-party, advertising or analytics cookies — the only cookie-like state is the session token, which is "strictly necessary" in every regime. Everything above derives from server-side request data the app already receives. A banner would be theatre.VERDICT
  • Privacy Notice: one new sectionDPDP wants processing named to the person: add a "product usage analytics" clause — what (session metadata: time, surface/OS, coarse location), why (improving the product, capacity planning), retention (13 months, then aggregates only), and that reporting is org-level aggregate. Ship it with the collector, not after.TO WRITE
  • IP handling rulethe IP is read in memory at login, resolved to city/state, and never written anywhere — the notice says exactly that. No raw-IP table exists to leak, subpoena, or breach.DESIGN
  • Small-cell suppressionany geography or org cell under 5 people renders as "hidden" — aggregate analytics must never function as a person-locator, including for us.DESIGN
  • Access control & auditPulse is platform-role gated and every view writes an audit row — the same discipline the DPDP attendance surface already follows. Employee-attendance figures stay counts; the per-person attendance surface remains god-mode-only as decided.DESIGN
  • Marketing site is separateif kartavaya.com's landing pages ever add third-party analytics or ad pixels, THAT needs a consent banner — the product app does not inherit that need, and keeping the two separate keeps the app banner-free.VERDICT

Ships as: a Pulse tab in the Hub, platform-role gated with an audit row per view; one read-only SQL module per card over existing tables (the same registry pattern the tenant analytics uses), so the first sixteen metrics need no schema change at all. The amber ones ride TWO deliberately boring collectors — one User-Agent + coarse-location parse at login (surface/OS matrix, states, cities) and one version header on phone API calls — plus the per-screen emitter if you ever want that one. Nothing here reads a tenant's business content: counts, names of orgs, and dates only — and the policy section above is the whole compliance bill: no cookie banner, one new Privacy Notice clause shipped with the collector.
