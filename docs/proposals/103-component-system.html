Creating things — and when the write fails

The most load-bearing motion in the product, because it is the only kind that stops the interface lying about state. MOTION-SPEC §7.1: optimistic renders at opacity .6 until acknowledged. §7.2: reversible destruction gets an undo, not a confirm.

The success path. Button goes busy → the row arrives immediately at opacity .6 with cursor: progress → the server acknowledges → it goes solid, the changed cell flashes, the counter bumps, and an undo toast opens. The row is on screen before the server has answered, which is what makes it feel instant, and it is visibly provisional until it is not.

The failure path, which does not exist today. animations.css records that .ix-rollback — the danger tint held for 1.6s after a failed write — "was declared here and applied nowhere, so no failed write has ever tinted anything". It was deleted rather than kept as a promise. Press Create & fail: the row shakes, holds the danger tint for a readable 1.6 seconds, then removes itself and says why.

Every effect above is token-driven. Accent glow is --glow, derived from --acc. The conic rim animates a registered @property --ang. The specular follows --mx/--my. Tilt writes --rx/--ry. All durations are the five rungs, all curves are the twelve named easings — so this whole system already passes check-motion.mjs and rides --ix.

Set Motion → None and every travel distance collapses to zero while every affordance stays: borders still change, states still read, the tick still marks. That is the accessibility floor, and it falls out of the arithmetic rather than a second set of rules.
