Liquid Glass

Proposal 88 · 2026-08-25 · frontend design-system customization

Apple-style liquid glass depth effects across every bordered surface in Kartavya, fully controlled from the Customization settings. The effect adds layered depth shadows, inset specular shine, and accent-tinted hover glow — without touching existing borders, backgrounds, or layout.

Customization controls

  • Glass intensity — range slider (0–1) controlling --glass-mix, which drives blur, saturation, and alpha across all glass surfaces.
  • Liquid glass preset — segmented control: Off / Subtle / Medium / Full. Sets data-liquid-glass attribute on :root.
  • Glass lens — toggle for a draggable SVG displacement-map lens (Easter egg). Uses the shuding/liquid-glass engine.

Live preview

The Settings → Appearance tab includes a live preview section showing KPI stat cards, dashboard cards, finance panels, rule cards, a mini table, toast, and quick-actions — all using real class names so they respond to live token changes. Changing the accent colour immediately updates the hover glow tint.

Architecture

CSS-driven, not component-wrapping

Early attempts wrapped components with <Glass> from @samasante/liquid-glass, which applies SVG feDisplacementMap for real refraction. This failed because all Kartavya surfaces have opaque backgrounds — there is nothing to refract through. The entire approach was scrapped in favour of CSS-only effects driven by the [data-liquid-glass] attribute on :root.

Token flow

applyPrefs()
  → sets data-liquid-glass="medium" on :root
  → sets --lg-accent (from acc.mid)
  → sets --lg-accent-deep (from acc.deep)
  → sets --glass-mix

liquid-glass.css
  → :root[data-liquid-glass="medium"] defines tokens:
      --lg-shadow, --lg-shadow-h, --lg-inset, --lg-shine,
      --lg-blur-add, --lg-scale-h, --lg-dur
  → selectors apply box-shadow + transition to 25+ class families
  → hover rule adds accent-tinted shadow + translateY(-1px) + scale

Why no border overrides

Three iterations tried adding border with !important or box-shadow outline rings (0 0 0 1px). Both clashed with elements that already carry coloured borders — selected sidebar-bg cards, pipeline stage buttons with --c colour, conversation-ground cards with accent borders, and is-on active states. The final version touches only box-shadow (depth + inset layers) and transform (hover lift), leaving all existing borders untouched.

Why no ::after pseudo-element

A ::after specular-shine gradient required position: relative on all targeted cards. This broke layouts where cards already had positioning, and caused text clipping when combined with cards that use their own ::after. The shine is now an inset box-shadow — same visual, zero layout side effects.

Accessibility

  • prefers-reduced-motion — disables transitions and hover transforms.
  • prefers-reduced-transparency — zeroes blur additions and disables shine.
  • useLiquidGlass() returns enabled: false when either media query matches.

Lessons learned

  1. SVG displacement needs transparency. <Glass> refracts what's behind the element. On opaque backgrounds, there's nothing to see.
  2. Never override borders with !important. Too many elements carry semantic borders (coloured left-border on pipeline stages, accent border on selected cards). Adding another border doubles up and looks crude.
  3. No position: relative on card selectors. Cards use diverse positioning strategies; forcing relative breaks layouts and clips text.
  4. No overflow: hidden on card selectors. Cards with content that intentionally overflows (badges, tooltips) get clipped.
  5. Accent colour belongs in diffused shadows, not outline rings. A 0 0 0 1px box-shadow acts like a border and clashes with existing borders. A diffused shadow (0 4px 16px) with 8% accent mix is visible on hover without competing.
  6. Generic class names are dangerous. .card catches too many unintended elements. Prefer the namespaced k-card, vk-card, etc.
