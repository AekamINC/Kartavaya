2 · The finding that reframes the inbox

Nearly half the task table had been written by test accounts. 351 of 736 tasks were created by a Playwright or QA login, and two of those logins held real user_roles in Unicode Group, a live organisation. One was an admin of “Keval To Do” and authored 13 of its 39 tasks.

That is why the task email you received looked like a leak and was not one: the test account was a genuine member, so every fan-out correctly included it. The bug was that the fan-out went to everyone; the test accounts merely made it visible.

Both are now fixed — the routing in code, the pollution in data. See sections 3 and 7.

4 · The structural backlog nobody is counting

Twenty-nine PROPOSED_* migrations have never run. Most are not drafts. Three groups matter, and the first one answers an inbox item.

PROPOSED_073 already diagnoses inbox item 1 — and it was written before today

Its own opening line: “An organisation cannot bring in a new person. At all.” Three causes, named in the file:

  • The only invite endpoint is POST /api/admin/invites, behind _require_admin — Aekam’s platform console. That is exactly your “the email has to already exist in Aekam Inc”.
  • org_members.add_member refuses anyone without an existing account, with a 404. That is the dead Add button.
  • There is no public registration. That is invite → register → “not part of any team”.

So inbox 1 moves from unverified to diagnosed with a fix already drafted. It is the highest-value item in this document, because it is the only one that stops a firm from signing up, and most of the thinking is already done.

The tenancy cutover is a six-phase programme stalled at phase one

PROPOSED_076–081 are one sequence: add org_id nullable, backfill, verify, constrain, retire team_members, enable RLS. None have run.

PROPOSED_080 carries its own warning in a box: “Steps 1-3 of the retirement sequence are NOT DONE. Running this file today breaks authorization across 17 backend modules and one live view.” It was written to record the sequence, not to be run.

6 · Storage

Test connection fails on credentials that work — the bug that blocked your new org. verify_r2_credentials tests by calling list_buckets, an account-level permission. A token scoped to one bucket — the least-privilege setup Cloudflare recommends — cannot list buckets, though it can read and write that bucket perfectly. It also never tests the bucket: R2Credentials carries bucket_name and the verifier is called with three of its four fields.

Sahayak images hide the user entirely. Both call sites pass folder="srijan/images" and a hardcoded user_id="system", under a random filename. Every image any person generates lands in one flat folder and the person who asked for it is never recorded on the file at all.

Full flow, both bugs, the one key grammar and a sketch of the Storage tab: proposal 83.
