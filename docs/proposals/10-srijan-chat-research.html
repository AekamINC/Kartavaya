Srijan chat — why it reads cheap

Brief, verbatim: "current one is very blank client wont buy it looks very cheap." Diagnosed against ChatGPT, Claude, Gemini, Perplexity, Copilot and Intercom Fin.

Method, stated honestly. This is a competitive and heuristic review, not user research — no customer was interviewed, so nothing here is a finding about real users. It is a structured comparison of six assistant interfaces against the current build, with the evidence for each claim taken from ChatTab.jsx itself. Treat it as a design argument, not as data.

It is not taste. It is eight omissions.

Every one of these is present in all six reference products and absent from ours. That is what "blank" and "cheap" decompose into.

MissingEvidence in our codeEffect on a buyer
Any identityEmpty state is "Pick a conversation, or start one."Nothing says what this is or what it knows. It could be any text box.
Markdown rendering{m.content} — the raw stringThe single biggest one. Every heading, list, table and bold the model produces renders as literal ## and **. The model writes well; the screen makes it look broken.
Suggested openersPlaceholder "Ask about this client…"A blank box demands the buyer invent a use case in the room. Most won't.
A real thinking stateLiteral text "Thinking…"Static text for 15 seconds reads as frozen. Our measured latency is 15.6s average.
Credible sourcesBare <span> with a similarity %A naked "87%" is meaningless. No link, no type, nothing to click.
Message actionsNoneNo copy, no retry, no feedback. Nothing to do with a good answer.
A composerSingle-line <input>Cannot write a paragraph. No Shift+Enter. Feels like a search bar.
AvatarsNoneTwo anonymous blocks of text.

Recommendations, by impact against effort

1 · Render markdownOne component. Turns every answer from raw ## and ** into a formatted document. Nothing else on this list changes the impression as much. Must stay escaped — Message.jsx's security note applies here too, so a parser that emits React elements, never dangerouslySetInnerHTML.
HIGH · ½ day
2 · The greeting, avatar and four openers"Hi, it's Srijan here." Fills the blank screen the buyer sees first, and the openers demonstrate the product without anyone having to think of a question.
HIGH · ½ day
3 · Sources that look like sourcesNumbered inline markers, a source list, and KB vs WEB labelled. We already return both shapes — the KB hit carries ref, similarity, source_type; the web hit carries title and url. Today both collapse into one grey span.
HIGH · ½ day
4 · Composer and message actionsTextarea, Enter/Shift+Enter, copy, retry, thumbs. The feedback also gives you the eval signal you asked for.
MED · ½ day
5 · An animated thinking stateThree dots instead of the word "Thinking…". At 15.6s average latency this is the difference between working and frozen.
MED · 1 hr
6 · StreamingThe real fix for latency, and the only item here that needs a backend change — SSE through the router. Worth doing, not first.
LATER · 2 days

Two constraints, both deliberate

No image generation from chat. Enforced server-side in the system prompt AND by not routing chat to any image provider — not merely by omitting a button. Images are 80% of the AI bill (measured: $1.73 of $2.15). A chat that mints them on request is the fastest way to lose control of that, and a client asking "make me a logo" is exactly the request that would.
Internet access, on. You want it, and it is currently dead twice over: grounding only fires when task == "chatbot", which the call site never passes, and ai_router.py's success return drops grounding_sources before the chat can read it. Two lines. But do not ship them until the source strip above exists — the moment web results blend into answers, a customer reading "from my knowledge base" is being misled unless the screen says which sentence came from where.
The honest headline. Items 1–5 are about two and a half days and need no backend work. But the reason it feels thin is not only the surface: the chatbot has been answering on a free model, with grounding switched off, against a knowledge base holding zero embedded chunks. Making it look premium while it still has nothing to think with would be the wrong order — the model chain and the index are a two-line fix and a backfill, and they should land first.
