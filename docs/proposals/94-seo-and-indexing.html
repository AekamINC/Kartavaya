Proposal 94 Aekam Inc · Kartavaya 2026-08-29

Google cannot see
the real product.

Kartavaya is not un-indexed because of a ranking problem. It is un-indexed because production serves a two-generation-old build, the crawler files do not exist, and the only host carrying the correct page is the one nobody meant to publish.

Method: live HTTP against production, staging and apex Rendered: headless browser, anonymous Source: working tree @ b3c70134

Every fix below is worthless until one thing happens: production is redeployed. Everything Google indexes today describes a product Kartavaya stopped being.

www.kartavaya.com currently tells the world it is “team task management built for agencies and founders” — a category owned by Asana, Trello and ClickUp, where a new entrant ranks nowhere. The build in main says something no global tool can say: practice management for Indian firms with GST built in. That page is live only on staging.

01

What is actually live

11 findings · verified

Nothing below is inferred from the repository. Each finding carries the command that produced it, in keeping with the house rule that a route or a file is never called missing without a live check.

P0 F1

Production serves a stale build with the wrong positioning

Evidence 
$ curl -sL https://www.kartavaya.com/ | grep -o '<title>[^<]*'
<title>Kartavaya — by Aekam Inc

# frontend/index.html in main says:
<title>Kartavaya — one place to run an Indian business</title>

$ curl -sI https://www.kartavaya.com/ | grep -i permissions
Permissions-Policy: geolocation=(), microphone=(), camera=()
# vercel.json says camera=(self) — the Pahchan fix is not deployed

# live CSP names the RENAMED, now-dead Railway host:
connect-src ... https://kartavya-production.up.railway.app

The rendered page is the old split login screen — “Do what must be done.” — with four bullets about Kanban columns. No modules, no GST, no pricing tiers, no आपकी भाषा. Three independent signals agree that this deploy predates the landing page, the Railway rename and this morning's camera fix.

Fix

Redeploy main on Vercel. Railway de-duplicates same-SHA deploys, so if the dashboard shows the head SHA already built, force a rebuild rather than trusting the badge. Verify by the title string, not by the deployment status.

P0 F2

robots.txt and sitemap.xml do not exist — they return HTML

Evidence 
$ curl -so /dev/null -w '%{http_code} %{content_type}\n' \
       https://www.kartavaya.com/robots.txt
200 text/html; charset=utf-8

$ ... /sitemap.xml   → 200 text/html; charset=utf-8
$ ... apex + staging → same

The SPA catch-all in vercel.json — { "source": "/((?!api/).*)", "destination": "/index.html" } — swallows both. Search Console will reject a sitemap that returns HTML, so the sitemap cannot even be submitted, and there is no way to keep a crawler out of anything.

Fix

Add real files to frontend/public/. Vite copies public/* into dist/ verbatim and Vercel serves a matching static file before it evaluates rewrites, so the catch-all stops swallowing them the moment the files exist. Contents in §3.

P0 F3

Staging is fully crawlable — and it is the better copy

Evidence 
$ curl -sI https://staging.kartavaya.com/ | head -1
HTTP/1.1 200 OK          # no auth, no X-Robots-Tag

$ curl -sL https://staging.kartavaya.com/ | grep -o '<title>[^<]*'
<title>Kartavaya — one place to run an Indian business

Staging is a publicly reachable duplicate of the site, and it currently carries the correct content while production carries the stale one. If Google finds it first — a single shared link is enough — the canonical version of Kartavaya on the internet becomes a hostname that runs against the production database, sits at OUTBOUND_MODE=dry, and holds the reseed test orgs.

Fix — two layers, in this order

Preferred: turn on Vercel Deployment Protection for the staging project. Authenticated deploys cannot be crawled at all, and it closes the exposure as well as the SEO hole. Minimum: serve X-Robots-Tag: noindex, nofollow on staging plus a Disallow: / robots.txt. Because vercel.json is shared between environments, generate the robots file per build mode — the repo already runs vite build --mode staging and already substitutes %VITE_*% into index.html, so a %VITE_ROBOTS% meta tag fits the existing mechanism with no new machinery. A header beats a robots rule here: Disallow stops crawling, not indexing.

P1 F4

No canonical tag, and the hostname is split

Evidence 
$ curl -sI https://kartavaya.com/ | head -2
HTTP/1.1 308 Permanent Redirect
Location: https://www.kartavaya.com/

$ curl -sL ... | grep -c 'rel="canonical"'
0

The edge already decides in favour of www, which is the right call and should simply be made official. But no page declares a canonical URL, and because every route serves the same index.html, the moment content pages exist they will all be indistinguishable to a crawler.

Fix

Add <link rel="canonical" href="https://www.kartavaya.com/"> to index.html now, and make it per-route when a head manager lands (§5). Use the Domain property in Search Console so apex, www and staging are all covered by one DNS verification.

P1 F5

The marketing page is client-rendered and lazy-loaded

Evidence 
$ grep -iE 'prerender|ssg|helmet|react-snap|sitemap' package.json
(no matches)

// App.jsx:112
const LandingPage = lazyPage(() => import('./pages/marketing/LandingPage'));

Every word of the marketing copy — the headline, fifteen modules, the GST claims, the four trust promises — exists only after JavaScript executes and a second chunk is fetched. Googlebot does render JS, but on a queued, budgeted second pass. Bing renders far less, and the WhatsApp, LinkedIn and AI crawlers that matter for a referral-led product mostly do not render at all — which for this product is the more expensive half.

Fix — and the trap inside it

Prerender the marketing route to static HTML at build time. The constraint: vercel.json pins a sha256 of the inline theme-bootstrap script in index.html, and scripts/check-csp-hash.mjs enforces it against public/_headers. Any prerenderer that reformats that inline script by a single byte changes the hash, breaks the gate, and — if it were forced through — would block the pre-paint bootstrap on the live site. Preserve the script verbatim, or regenerate the hash in the same commit.

P1 F6

Every unknown URL returns 200 — soft 404s at scale

The catch-all rewrite means /anything-at-all answers 200 OK with the same document. Google classifies these as soft 404s, which burns crawl budget and can suppress the pages that matter. It is harmless at a five-page site and becomes a real drag the moment content pages exist.

Fix

Ship alongside the head manager in §5: an unmatched route renders a 404 view carrying <meta name="robots" content="noindex">.

P1 F7

No share image and no structured data

og:image is deliberately absent, and the reasoning in index.html is sound — a broken preview is worse than none. But the same comment records that most visits arrive from a WhatsApp link, which makes this the highest-leverage single asset on the site and the one piece of the funnel that has no substitute. There is also no JSON-LD anywhere, so Kartavaya is not eligible for an organisation knowledge panel or sitelinks.

Fix

A real 1200×630 of the product — the actual task board or an invoice, not a logo on a gradient — at /og-kartavaya.png, then uncomment the tag. Add Organization, SoftwareApplication and a FAQPage block; the four Trust claims are already written in question-and-answer shape.

P2 F8

Payment and signing links are crawlable — and Googlebot is named explicitly

Evidence — vercel.json 
"source": "/i/:token",
"has": [{ "key": "user-agent", "value":
  ".*(whatsapp|facebookexternalhit|...|googlebot).*" }],
"destination": "/api/og?token=:token"

/i/:token (payment), /sign/:token (eSign), /approve, /accept-invite and /reset-password are all public, token-bearing URLs, and the OG rewrite deliberately hands Googlebot a card for payment links. Low probability, high embarrassment: one such URL pasted into an indexed page is enough.

Fix

Disallow each prefix in robots.txt, and drop googlebot from that user-agent list — it is a social-preview rewrite, and a search crawler has no business there.

P2 F9

/glass-demo is a public, unauthenticated route

Declared in App.jsx:189 above the protected tree. A design demo page is not something to rank for, and it dilutes a five-page site. Disallow it, or move it behind auth.

P2 F10

The live landing page contradicts itself in Devanagari

Modules.jsx carries a long comment establishing that CRM is ग्रह and explicitly not ग्राहक — which means customer and is already spent on a different sidebar heading. The rendered page obeys it in the module grid and then breaks it about four hundred pixels lower, where the access-control fragment in Features.jsx renders ग्राहक · CRM. Both are visible on staging right now, on one screen.

Fix

One word in Features.jsx. Worth doing before the page is advertised.

P2 F11

The only conversion path is a WhatsApp link to a UK number

VITE_LEAD_CTA_HREF resolves to https://wa.me/44… on staging — a +44 number, on a page whose entire argument is that it was built in India for Indian firms. It is also the sole destination: hero, pricing and footer all point at it. Traffic from every phase below lands here.

Fix

An Indian number, or the lead form described in cta.js option 2. Whichever is chosen, it has to exist before any of this drives traffic — otherwise indexing succeeds and the funnel still ends nowhere.

02

The sequence

order matters

These phases are strictly ordered. Submitting a sitemap before the redeploy would ask Google to index the wrong product faster, and a first impression of the index is expensive to correct.

PHASE 0

Make the site truthful and crawlable

Day 1 · half a day
  1. Redeploy main to production. Nothing else in this document may start before this lands.
  2. Add frontend/public/robots.txt and frontend/public/sitemap.xml (§3).
  3. Add the canonical tag to index.html.
  4. Block staging — protection, or noindex header plus robots (F3).
  5. Drop googlebot from the /i/:token user-agent list.
  6. Fix the ग्राहक → ग्रह word, and point the CTA at a destination that suits the audience.
Exit test

curl -sI https://www.kartavaya.com/robots.txt returns content-type: text/plain, and the homepage title reads one place to run an Indian business. Both, or the phase is not done.

PHASE 1

Register and ask to be crawled

Day 1, after Phase 0 · 1 hour
  1. Google Search Console, Domain property for kartavaya.com, verified by DNS TXT in Vercel DNS. This covers apex, www and staging together — a URL-prefix property would miss the redirect target.
  2. Submit https://www.kartavaya.com/sitemap.xml.
  3. URL Inspection → Request indexing on the homepage. This is the one manual nudge worth spending.
  4. Bing Webmaster Tools — import the GSC property rather than re-verifying. Bing feeds ChatGPT and Copilot answers, which for a B2B product is no longer a rounding error.
  5. Confirm in GSC that staging is reported as excluded by noindex. That is the proof F3 is closed, not the absence of a staging result.
Exit test

Sitemap status Success with 5 URLs discovered, and the homepage returns URL is on Google within roughly a week.

PHASE 2

Make the one page worth ranking

Week 1 · 1–2 days
  • Title. The current one is 52 characters and reads well, but carries no category term. Keep the voice, add the noun: Kartavaya — practice management for Indian firms. Resist stuffing; a title a human would say out loud outperforms a keyword list.
  • H1 stays as it is. Practice management that speaks आपकी भाषा already carries the category term and is the most memorable line on the site. It does not need editing for a crawler.
  • og:image at 1200×630, then uncomment the tag (F7).
  • JSON-LD: Organization, SoftwareApplication, FAQPage built from the four Trust claims.
  • Give the four legal pages — privacy, security, DPA, sub-processors — their own titles once the head manager lands. They are around a thousand words each of genuine, specific content, and they are the pages a cautious buyer reads before trusting anyone with a client's GSTIN.
PHASE 3

Build pages that can rank at all

Week 2 onward · continuous

A single page ranks for one thing: the brand. Every non-brand query in §4 needs a page pointed at it. This phase has a hard technical prerequisite — per-route titles and descriptions, which means the head manager and prerender from F5. Do not write content before that exists; it would all share one title.

  • /gst-invoicing — HSN and SAC, CGST/SGST/IGST, place of supply, LUT export invoices, GSTR-1 and GSTR-3B summaries. The strongest page available, because the product genuinely does this.
  • /client-approvals — approval by link, no account, no software, decline with a reason. Nothing in the global category does this the same way.
  • /practice-management — the category page the title now claims.
  • /payroll and /attendance — Vetana and Pahchan, including biometric attendance.
  • Comparison pages only once the above rank. They attract the highest intent and the most scrutiny; a thin one damages trust.
Write only what is shipped

The house rule that a feature is done only when a customer completed the flow applies with more force here than anywhere in the codebase. An unshipped claim in the product is a bug; on an indexed page it is a promise to a stranger, cached by Google, quoted back by an AI assistant, and read by someone deciding whether to trust you with bank details.

PHASE 4

Off-page, within the rules that bind this market

Month 2 onward
  • Google Business Profile for Aekam Inc, and a LinkedIn company page. Both are entity signals that support a knowledge panel; both are free and neither is optional for a firm asking to be trusted.
  • India-relevant software directories — SoftwareSuggest, Capterra India, G2. These rank for comparison queries the site will not touch for a year.
  • Referral is already the channel; give it a surface. A short, linkable page a referring accountant can send is worth more than any keyword on this list.
The constraint that rules this phase out of outbound

ICAI rules bar soliciting professional work from prospective clients by email, and the audience here is largely chartered accountants. Off-page work must be inbound, directory and referral-shaped. Cold prospect email is not a channel available to this product, which is precisely why organic search matters more than it would elsewhere.

     door, not a destination, and it competes

Do not hand-edit public/_headers

It is generated from vercel.json and enforced directive-by-directive by scripts/check-csp-hash.mjs. If Phase 0 adds a header, change vercel.json and regenerate. The file's own comments record four separate defects that a hand-edit introduced last time, including switching the Pahchan camera back off.

04

What to rank for

5 clusters

There are no search volumes in this table, deliberately. No keyword tool is authorised in this session, and an invented volume would be indistinguishable from a measured one to everyone downstream. Pull the real figures from Search Console once data exists, or from Ahrefs before committing budget to a cluster. The clusters, intent and ordering stand on their own.

Cluster Representative queries Intent Lands on When
Brand kartavaya · kartavaya aekam · kartavaya login Navigational. A referred prospect checking you are real. / Phase 0
Category practice management software for CA firms · accounting practice management India · CA office management software Commercial. The buyer already knows the category exists. /practice-management Phase 3
Job to be done GST invoicing software · GSTR-3B tracking · LUT export invoice format · client approval workflow Commercial and problem-led. The sharpest fit to what is built. /gst-invoicing · /client-approvals Phase 3
Comparison … alternative · best practice management software for chartered accountants Highest intent, highest scrutiny, hardest to win. comparison pages Month 3+
Informational HSN code invoice format · GSTR-1 vs GSTR-3B · place of supply rules Authority-building. Brings accountants, not buyers. guides Month 4+
Be honest about what SEO is for here

Kartavaya is invite-only. There is no public sign-up route, no sign-up endpoint, and that is a settled decision rather than a gap. So organic search is not a volume lead-gen channel and should not be resourced as one.

Its three real jobs: own the brand name, so a referral does not lose the prospect at the moment they search; survive diligence, because the security, privacy and DPA pages are what a firm reads before handing over client GSTINs; and capture the category over twelve months, in a niche where global tools cannot credibly compete on GST. Judge it on the first two for at least two quarters.

05

What good looks like, and when

expectations
HorizonExpectMeasured by
Week 1 Homepage indexed. Sitemap accepted, 5 URLs discovered. Staging reported as excluded by noindex. GSC · Pages · URL Inspection
Week 2–4 Brand queries rank first. Legal pages indexed. First non-brand impressions appear. GSC · Performance, brand filter
Month 2–3 Content pages live and indexed; long-tail GST queries begin surfacing. Directory listings live. Indexed count vs sitemap count
Month 6–12 Category queries on page one. This is the realistic horizon for a new domain in a competitive niche — anyone promising it sooner is selling something. Position for the §4 category cluster

The single number to watch first is not traffic. It is indexed pages versus sitemap pages. Until those match, ranking work is premature, and a gap between them is the earliest signal that F2, F3 or F5 has quietly come back.

06

What this document did not do

scope
  • Nothing was changed. No file was written to frontend/, no deploy was triggered, no DNS record touched. This is a plan; Phase 0 is roughly half a day's work whenever you want it.
  • No search volumes were estimated. See §4.
  • Competitor rankings were not measured. That needs a keyword tool; the marketing connectors in this session are unauthenticated and cannot be reached from a non-interactive run.
  • The stale production build was diagnosed, not explained. Three signals establish that production is behind. Which SHA it is actually running, and why the Vercel project did not follow main, is a separate question worth answering before the redeploy so it does not recur.
