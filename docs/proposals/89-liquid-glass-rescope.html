Proposal 89 · Design system

Liquid Glass — the rescope

Where the glass layer applies today, where Apple's own rule says it belongs, and the free techniques worth borrowing. The verdict is mostly subtraction: the architecture is right, it is aimed at the wrong 22 surfaces, and its first paint is worse than the effect turned off.

2026-08-25 · verified against staging @ 7a2f7397 · every line number read live · one file, ~1 day of work

The one-paragraph version. liquid-glass.css is 194 lines, 2.2 kB gzipped, zero JavaScript, and token-driven — the engineering is sound. But it names 39 targets and 9 of them are not surfaces (they have no background, so the layer draws a shadow around a transparent box); 6 of its 8 backdrop-filter rules render nothing or make the surface less glassy; and because the preset tokens live only under [data-liquid-glass="…"] — an attribute nothing sets before React mounts — the entire first paint renders shadowless. Apple's guidance is that the material belongs to the floating layer, not content cards; this layer puts it on 22 content cards. Fixing it is a day inside one file, and items 1–9 touch no component at all.

The backdrop-filter problem

Sixteen backdrop-filter declarations across 8 rules. Six can never render because the element behind them is opaque hex in both themes — .tbl th (var(--s-low)), .tst (var(--s-lowest)), .k-dock (var(--surface)). A backdrop-filter forms a compositing layer per element and re-samples on every scroll frame, so .tbl th on the invoices register is ≈14 blurred sticky layers producing zero pixels of output. Five more are downgrades: at the default mix the layer's flat blur is below what .modal__panel, .pop, .pk__pop, .menu--float and .mnav already set for themselves — so turning glass on makes the modal less glassy. Only .top and .k-cmdk get a real increase.

2What is wrong — ranked

Performance first, for the 1366×768 integrated-graphics laptop this product is used on.

P1Six backdrop-filters that render nothing, one compositing layer per table column. .tbl th is sticky + opaque; ≈14 blurred layers re-sample while 25 rows scroll under them, for zero output. .tst and .k-dock are the same defect at one element each. The repo already states the rule being broken. Fix: delete 6 declarations.

P2The invoice table scales on hover. .tv-card is not a tile — it wraps the toolbar and the whole scrolling table. A fractional scale() over ~400 cells plus every sticky header re-rasterises tabular text on ordinary mouse travel, and widens exactly the overflow viewport-fit.css exists to fight. Fix: remove one identifier.

P3Every glass rule fires at first paint with all 7 tokens undefined. The tokens live only under [data-liquid-glass="subtle|medium|full"]; index.html's bootstrap sets data-theme, data-conv-* and data-platform but not this one, and applyPrefs runs in a mount effect after paint. So the first frame renders box-shadow:none on every card, modal, drawer, toast and sidebar — strictly worse than glass off. Fix: one bare :root{} block.

P4No dark arm on either shadow token. The dark blocks redefine only the highlights; --lg-shadow stays rgba(0,0,0,.03–.05) in dark, where the house tokens move to .5–.9 precisely because black-on-near-black is invisible. Cards lose their depth in dark mode. This is the "legible in both themes" failure.

P5Reduced-transparency is defeated on 4 overlays. The codebase's opt-out (components.css:1374) is out-specificity'd by the glass layer, so an OS request to reduce transparency loses. And --lg-shine:none never applies in dark.

P6Glass destroys the .hcl-card focus ring. The base rule sets box-shadow unconditionally at higher specificity, so :focus-visible's halo never paints — the exact regression workflow.css already recorded fixing once.

P7Reduced-motion misses 6 movers — .k-hero-kpi__card (three on the first screen), .vk-card, .vk-pl__st, .vgw-kpi, .gr__card, and .sr (which snaps 1px instead of easing).

P8Glass on 9 non-surfaces (table above) — shadows and shine around transparent boxes, one of them the tab wrapper on 13 pages.

P9–P10Silent replacement of designed states — .niyam-card's family-tinted glow and .mkt-card's lift are overridden with no note, mouse and keyboard now disagree on the same card, and .side loses its hand-built specular edge.

3Where it should be

Apple's rule, and the layer breaks it. HIG Materials: "Don't use Liquid Glass in the content layer… use standard materials for elements in the content layer." The material belongs to the floating navigation and control layer. 22 of the 26 classes in the base list are content layer. So the answer to "757 surfaces are uncovered" is: that is correct. Content cards already carry --shadow-1; the layer's job on them is to scale that, not replace it. The repo has already written this argument down, for the Kanban card the scan called the biggest gap — .bc is deliberately flat. Do not glass it.

Everything else the scan flagged as "missing" is content layer and stays flat.

4The lightweight recipe

Replaces the token blocks and the reduced-motion list. The accessibility escape stops being a duplicated selector list and becomes three token flips — so the two lists cannot drift again. Full drop-in is in scratchpad/glass-plan.md; the core is:

/* 0 · Defaults on bare :root — the first paint is the finished paint. */
:root {
  --lg-accent:   var(--k-mid);
  --lg-shadow:   0 1px 4px rgba(0,0,0,.04), 0 6px 20px rgba(0,0,0,.035);
  --lg-shadow-h: 0 4px 16px color-mix(in srgb, var(--lg-accent) 8%, rgba(0,0,0,.06)),
                 0 14px 44px rgba(0,0,0,.05);

  /* Four-sided rim — light wraps a curved edge at falling intensity,
     not a single top bevel. One token, ~30 consumers. */
  --lg-rim:  inset 0  1px 0 rgba(255,255,255,.50),
             inset 0 -1px 0 rgba(255,255,255,.18),
             inset  1px 0 0 rgba(255,255,255,.14),
             inset -1px 0 0 rgba(255,255,255,.14);

  --lg-blur-x: 1.30;   /* a MULTIPLIER of each surface's own blur, never a flat addend */
  --lg-lift: -1px;  --lg-scale-h: 1.005;  --lg-scale-p: .997;  --lg-dur: .3s;
  --lg-r-inner: max(2px, calc(var(--r-lg) - var(--pad-card, 16px)));  /* concentric radius */
}

/* 1 · Dark — shadows too, not just highlights (house tokens go .07 → .5). */
:root[data-theme="dark"] {
  --lg-shadow:   0 1px 4px rgba(0,0,0,.34), 0 6px 20px rgba(0,0,0,.30);
  --lg-shadow-h: 0 4px 16px color-mix(in srgb, var(--lg-accent) 10%, rgba(0,0,0,.42)),
                 0 14px 44px rgba(0,0,0,.38);
  --lg-rim: inset 0 1px 0 rgba(255,255,255,.12), inset 0 -1px 0 rgba(255,255,255,.05),
            inset 1px 0 0 rgba(255,255,255,.04), inset -1px 0 0 rgba(255,255,255,.04);
}

/* 6 · Accessibility — both are token flips, no parallel selector lists. */
@media (prefers-reduced-motion: reduce)       { :root { --lg-lift:0px; --lg-scale-h:1; --lg-scale-p:1; --lg-dur:.001s; } }
@media (prefers-reduced-transparency: reduce) { :root { --lg-blur-x:0; --lg-shine:none; } /* + a property-cancel rule */ }

/* 5 · Squircle — progressive, Chrome/Edge 139+; everyone else keeps radius. */
@supports (corner-shape: squircle) {
  :root[data-liquid-glass="full"] :is(.k-card,.modal__panel,.sheet,.k-cmdk,.k-dock,.pop) { corner-shape: squircle; }
}

5What to take from outside

Take nothing as a dependency. Every free React glass library is Chromium-only for real refraction, or a second component system fighting k-*, or unmaintained. You already ship one earning nothing. The value is in three techniques and one deletion.
