The sidebar glass, and why it looks like nothing

You said the effect is “nearly useless” on Windows and suspected it is no better on a Mac, since both run in a browser. You are right, and the reason is not the platform.

Hover the rail on the right-hand panel · click a module

The actual cause

backdrop-filter blurs what is behind the element. Behind our sidebar is a flat page background — #F3EFE6 in light, #0C0E11 in dark. Blurring a flat colour returns that same flat colour. The effect is running correctly on every machine and producing, by arithmetic, nothing.

So the Windows override is treating a symptom. Turning glass off where it looks like nothing is reasonable, but it was never a Windows problem — it is a contrast-behind-the-glass problem, and it is equally true on a Mac. Move the ground with the button above and watch the left panel: the current treatment only becomes visible when something is actually passing under it, which on a static page is never.

Four of the six cost nothing to composite. That is the point: on a machine that cannot afford backdrop-filter, the sidebar still gains the gradient, the specular edge, the grain and the sliding lozenge — so it looks deliberate rather than switched off.

The recommendation, against the decision already on file

The recorded decision is glass everywhere, gated on whether the device can render it rather than on which OS it is. I think that decision stands and the Windows override should be deleted, not extended — but it only stands once the glass has something to be glass about. Panel B is that. The single branch left is @supports not (backdrop-filter) plus the two accessibility queries, and none of the three mentions an operating system.

If after seeing panel B you still want Windows solid, that is a one-line change and I will make it — but it would then be a taste decision rather than a fix, and worth recording as one.
