The Niyam catalogue

How many automations should you expect to see? Today: 13 starter templates in the picker, one live rule, and an engine that hears 11 kinds of event — but only Tasks and the CRM actually speak. This plan takes the same sweep-and-registry method that carried analytics into every module and applies it to automation: every module declares its events, every module ships its starters, and the number in the picker grows from 13 to roughly 37.

2 · Repair before build: two broken contracts

Three approval paths finish tasks silently. The engine’s founding contract is “every status write emits” — but _approve_task_mark_done (server.py:2511) and both magic-link approval endpoints (approvals_router.py:682, 755) write task status with no event, slipping past the parity ratchet because their SQL begins UPDATE tasks SET approval_status=. A “when a task is finished” rule does not fire when the finish came through an approval — which is precisely when it matters.
Winning an order wins the deal invisibly. Closing a Vikray order writes graha_deals.stage='Won' directly (vikray.py:502–507), bypassing the deal-stage emitter. A “deal won” rule fires from the CRM board but not from sales — the same fact, two behaviours.

Both are half-session fixes and go first (N7). Alongside them, four console nits found in the sweep: no Delete control (the API exists), the editor offers changing a rule’s trigger but the API ignores it, Preview’s “would do” detail is returned and never rendered, and the newer rule families have no filter chip.

3 · The catalogue, module by module

The analytics method, reapplied: each module declares its events in the registry (typed payloads, emitted in the same transaction as the business write), the sweep gains the module’s temporal questions, and each module ships 2–4 starter templates. Events marked ⚠ carry an owner decision. Every emitter retrofit follows the two rules the research surfaced: the handler gains a per-write transaction (most write via bare pool.execute today), and the new event type is cleared from UNWIRED only when its emitter actually lands.

4 · New verbs — the allowlist grows by two

  • task.create — “make a follow-up task”: title template, project, assignee tokens. The onboarding-checklist and deal-won starters need it. Same system-account authorship as task.add_comment.
  • report.send — renders a module report (proposal 65 S2) and emails it to staff tokens. This is what makes scheduled reports a Niyam rule instead of a second delivery system.
  • Deferred: whatsapp.send_template (paid, owner decision). Still zero verbs that move money, still zero model calls.
