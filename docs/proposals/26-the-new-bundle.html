2The three real gaps

1 · The organisation switcher does not exist as designed

It exists as components/layout/OrgSwitcher.jsx — 81 lines, a <select> in the sidebar footer reading /v1/org/memberships. Not one .orgsw* class appears anywhere in frontend/src.

I opened the prototype at 1440px and read the popover out of the live DOM. This is what it actually contains:

YOUR ORGANISATIONS
AI  Aekam Inc  — Owner · 18 of 25 seats
MA  Mehta Associates  — Admin · 7 of 10 seats
ST  Sundar Textiles  — Editor · at seat limit — 45 of 45

SUPPORT ACCESS · APPROVED
VT  Vardhman Traders  — SR-2418 · approved by R. Iyer · ends in 2h 14m
“Not a membership. Time-boxed, written to their audit log, and their owner was emailed when it opened.”

Aekam platform console — Cross-org operations · not a tenant view

Three sections, and each carries something the current control cannot say:

  • Seat counts, inline. organisations.max_users is enforced and set by hand per org, so an org sits at its ceiling with nothing on screen until somebody fails to add an employee. at seat limit — 45 of 45 in --warn is the cheapest place to make a commercial limit visible before it is hit.
  • Support sessions, in platform violet — never the user's accent — with an inset 2px rule, the request id, who approved it, and a live countdown. The trigger keeps a support · 2h 14m tag so an operator with two tabs open is never unsure which one they are typing into.
  • The console as one row, below a rule. The prototype had one topbar chip doing two unrelated jobs — naming the active org and toggling the console. A single control that answers “whose data am I in?” and “am I an operator right now?” cannot show the state of either.
One constraint in that spec is now out of date, in our favour. It says “the X-Org-Id header bypass is never audited at all. Ten accounts can currently resolve into any org through it.” That was true when it was written and is not true now — the header was narrowed to four console path prefixes earlier today, and get_visible_team_ids no longer returns every team in the database. The switcher's other constraints stand: memberships and approved sessions only, never the platform-wide org list, and an expired session must drop the user back to their default membership with an explanation rather than silently keep working.

It also names a cache correctness bug worth fixing at the same time: switching orgs must clear cached module gates. Module access is cached for 5 minutes, so a stale gate shows one org's entitlements inside another.

2 · The conversation ground — a whole per-user setting, absent

tokens.css gains five motif tiles as data URIs and two axes stored per user beside accent and density: data-conv-pattern (none | jaali | patola | star | lines) and data-conv-ground (warm | paper | deep | accent). Each motif is restated for dark, because a warm stroke sampled from cream turns muddy on #0C0E11 rather than merely dark.

In the build: zero files reference --motif-jaali, data-conv-pattern or data-conv-ground. Nor the four element shadows the same change adds — --shadow-card, --shadow-block, --shadow-seat, --shadow-bubble, which exist because those shadows were literal warm rgba() inside sahayak.css and messaging.css and so could not flip theme.

A sixth ground, kamal, is to be drawn from the lotus: rosette course only, ten lobes r34–r70 plus the r32 eye, one pen, one colour, rotated off-axis with alternate rows offset so it cannot grid up into a watermark. lotusLobe() already returns the path — the instruction is explicit that it must not be redrawn. We do have components/brand/Lotus.jsx and BrandLoader.jsx, so the geometry is in hand.

Good news on the same page: the type scale is already derived from --font-size-base in kartavaya-design.css. The bundle flags absolute px as a defect that made the Text-size slider a no-op on everything but body copy. Ours is calc() throughout, with the max() floors on --t-label and --t-label-sm. Nothing to do.

3 · Sahayak's palette is reversed — and it costs a contrast pass

Decision, 2026-08-06: Sahayak ships on the product's cream palette, matching this prototype exactly. The change itself is one line: remove k-surface-theme from .sh.

We ship the opposite. pages/sahayak/SahayakTab.jsx:413 renders <div className="sh k-surface-theme">, which resolves every token to the Slate / indigo palette. The layout, spacing and type are not in question and do not change — only the scope.

The cost is not the one line. That file's contrast work was measured by hand against Slate and indigo specifically, because check-contrast.mjs has no model of scope and measures every pair against cream regardless. Removing the scope voids every one of those measurements, and the gate will not tell us — it never saw them. --mc is worse: it is declared only on .sh-ac[data-kind], never at a theme root, so the checker skips those rules entirely. The pairs named for re-measurement first are --primary-text on --primary-container, --on-surface-3 on --surface, and --warn on --surface.

I ran Sahayak.html and confirmed the intent directly: cream ground, jaali texture behind the thread, bilingual tabs (Ask प्रश्न · Skills कौशल · Content सामग्री · Knowledge ज्ञान · Credits व्यय), and a Thinking state that names each work step with its cost — “Read overdue invoices · free”, “Wrote the summary · analysis · 2 credits” — while the sources panel stays empty until there is something true to put in it.

5What I would do, in this order

  1. The org switcher. Highest value per hour in the set: it is the control a two-firm user cannot work without, it surfaces the seat ceiling before somebody hits it, and it puts support access somewhere an operator sees it. Includes clearing cached module gates on switch, and the mobile placement (into the slide-out sheet, not the 44px topbar).
  2. Token layer. Conversation ground plus the four element shadows. Everything in 28 and 29 sits on these, and doing them late is what produced eight disagreeing status-colour maps last time.
  3. Sahayak's palette flip, with the contrast pass. One line and a measurement session. Not shippable without the second half.
  4. include_reply_counts. A query change that unblocks the whole of 28.
  5. Messaging v2 and the marketplace. The largest two, and both want the vocabulary above to exist first.

Items 1–4 are each small and independently shippable. Item 5 is the real body of work.
