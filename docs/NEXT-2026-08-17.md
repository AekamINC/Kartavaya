## What the system account needs (research done, no code written)

- `public.users` is the table (unqualified — public schema). `user_id` is TEXT,
  and `password_hash` / `salt` / `email` / `name` are all NOT NULL.
- Shape: one row per org, `user_id = 'niyam:<org_id>'`, name `Niyam`, an
  unroutable email, and a password hash no input can produce. Add
  `is_system BOOLEAN NOT NULL DEFAULT FALSE` and refuse it at the login path
  explicitly rather than trusting the sentinel hash alone.
- **Seats:** `org_invites.count_seats` counts DISTINCT `user_roles.user_id`
  holding a `SEAT_ROLES` code, so the account must NOT hold one of those codes.
  `SEAT_ROLES` is built from `middleware/role_tiers.SEAT_CONSUMING_ORG_ROLES`;
  `user_roles.role_code` has a CHECK list in migration 016 that a new `system`
  code has to be added to.
- **Where it must not appear:** member lists, @mention pickers, team counts.
- Why it matters beyond tidiness: `services/niyam/actions.py` says outright that
  `task.add_comment` is missing because the comment read path INNER JOINs
  `users`, so a comment from a non-existent author is invisible to everyone.
  This account is what unblocks that verb.
- Next migration number is **148** (147 is `suppressed_is_a_status`).
