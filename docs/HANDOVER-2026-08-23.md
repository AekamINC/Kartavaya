## 2. What is on staging that was not there yesterday

The list matters because several of these are behaviour changes, not features.

- **A firm with no account can be onboarded.** `create_org` used to 404 with
  "they must register first", which describes a registration flow this product
  does not have. It now creates the org and invites the owner. It also creates
  the founding project (it used to 400 until the customer had made one
  themselves) and seats the founder as `org_owner` — a role that had **no
  reachable writer anywhere**, which is why no organisation could switch its
  own modules on or off.
- **Project membership reads `project_assignments`, everywhere.** ~40 reads
  across 24 files. Three defects fell out: a removed member kept the org's
  projects, a deactivation revoked nothing, and an owner seated only in the new
  table was refused their own project's default template.
- **`GET /api/time/report` had NO org scope.** A platform account got all 108
  time entries of all three organisations in one list. Fixed, staff included.
- **GSTR-3B counted draft invoices** — ₹1,42,607 of cash tax removed for one
  org in one month. **CRM "Won value" windowed on the wrong date** — 39% low on
  one org's financial year.
- **Punch photographs had never worked for two of three orgs** (the guard
  compared a key that already carried the tenant prefix). 1,659 punches, zero
  photos.
- **One storage key grammar**, and the Storage tab that reads it.
- **107 tables are arrangeable**; `updated_by` went 3 → 64.
- **`skill_ack` wired across all 32 skills that need it** — 77 skills used to
  repeat their findings for ever.
- **`cron-report-dispatch` armed** at `7 * * * *`, and `publish` removed from
  `cron-daily`.

### H · Compliance as a setting — not started

`docs/proposals/80-*.html` is the spec and the owner's rule is written down in
it: *"build everything. org who is going to market is not our problem… they
have to comply not us."* Everything exists; what varies is a setting with the
safe default, audited, with the consequence stated next to the control.

**Do not build a setting that makes a compliance CLAIM.** There is no SOC 2, no
ISO 27001 and no DPDP certification. "This org has chosen X retention window"
is a fact; "we are compliant with X" is a lie the customer would repeat to
their own regulator.

One live constraint to respect: **migration 196 refuses per-scope retention
overrides**, because retention is a DPDP promise made to every person in an org
in one notice quoting one number.

## 5. Things that cost time tonight — read before repeating them

- **Stale `__pycache__` produces phantom failures.** Source-inspecting tests
  read a file whose line numbers have moved. Always
  `find . -name __pycache__ -not -path "./.venv/*" -exec rm -rf {} +` then
  `python -m pytest -q -p no:randomly`. Consecutive runs of an unchanged tree
  gave 82, 34, 15, 2, 1 and 0 failures before this was understood.
- **Two tests were right only some of the time, and both were found by
  refusing to dismiss a failure that "passes in isolation".**
  `test_inbox_triage` compared fixtures dated from local `date.today()` against
  code using `utc_now().date()` — wrong for 5½ hours of every day in IST. And
  `test_prachar_drip` asserted a three-letter local part was absent from a
  233-character base64 token: measured at **122 of 20,000 tokens (0.61%, ~1 run
  in 164)**, while the full address appeared 0 times. The property never
  failed; the assertion did.
- **`org_id IS NULL` is a VALUE in this schema, not an absence, and it means
  something different in each table.** In `user_roles` it is how a platform
  grant is stored. An agent read three separate NULL populations as one
  invented "fourth organisation"; the query that tells them apart is
  `WHERE org_id IS NOT NULL AND o.id IS NULL`, which returns zero.
- **Verify a claim before putting it in front of the owner.** Three of the
  session's stated premises were wrong: "an organisation cannot bring in a new
  person" (`org_invites.py` already existed), "41 of 301 tables" (265 base
  tables, ~26 that are record lists), and the fourth org above.
- **A narrowing that removes cross-tenant rows is not a decision to escalate.**
  It can only ever remove a wrong row. Measure both counts; if they match, land
  it.
